# 2026-08-13 QQ 新 API 补齐计划

## 1.1.0 范围

- 版本从 `1.0.23` 升级至 `1.1.0`。
- 本版本只实现 QQ 官方 V2 流式消息、指令面板、单聊全局自定义菜单和对应 Console 管理页面。
- 群成员详情、分享链接、订阅消息授权事件、输入状态通知、互动召回和图片校验等 API 延后处理。

## 流式消息

- 提供官方 V2 单聊流式内部 API `bot.internal.sendStreamMessage()`，对应 `POST /v2/users/{user_openid}/stream_messages`。
- 提供高层 `bot.stream()` 会话对象，由调用方通过 `write()` 连续写入生成片段，并通过 `end()` 发送完成包；会话自动维护 `stream_msg_id`、`index` 和被动回复字段。
- 默认消息策略为普通发送，以保证成功率。
- 配置保留三种流式能力：私聊官方 V2、私聊旧版兼容、群聊旧版兼容。默认只启用私聊官方 V2；旧版兼容能力默认关闭并标注为非当前公开 API 保证范围。
- V2 默认策略可选普通发送、立即完成、模拟逐段；模拟逐段默认每 80 字、200 毫秒，明确标注额外延迟与失败风险。

## 指令面板和菜单

- 增加强类型内部 API：指令面板列表、创建、详情、修改、删除、关联对象，以及单聊全局自定义菜单查询和修改。
- Console 左侧导航始终注册 QQ 指令面板页面；`enableCommandPanel` 默认开启。显式关闭时页面保留并提示启用条件，不创建数据库记录、不调用面板 API。
- 启用时只同步 Koishi 顶层且 `slash=true` 的命令，默认支持 `c2c` 和 `group` 场景。
- 支持手动选择排序、字典序前 20、字典序后 20、随机 20 四种模式。默认 `manual`，由 Console 管理；自动模式在适配器就绪后同步，随机模式在每次插件加载或重载时重新选择。
- 手动模式由 Console 左侧导航的“QQ 指令面板”独立页面按 QQ Bot 持久化命令选择、顺序和场景，预览后手动同步。
- 命令名或描述超过 QQ 限制时跳过并显示原因；不自动截断。
- 只管理 `remark` 带适配器专属标记的面板，绝不修改用户自行创建的面板。
- Console 页面同时提供全局自定义菜单的查询、编辑、预览和手动同步，权限等级为 3。

## 2026-08-13 文档对照补充

以 QQ 官方文档仓库 `76e9351` 为基准，本 fork 已覆盖本版本范围内的 V2 流式消息、指令面板和单聊全局菜单。下面列出官方已有、但适配器尚未形成完整类型封装或 Koishi 能力映射的内容，留待后续版本按优先级实施。

### 建议优先处理

- **输入状态通知**：普通单聊发送接口支持 `msg_type=6` 与 `input_notify`，可在真正开始流式前展示“正在输入”。当前 `QQ.Message.Request` 未声明字段，也没有 `bot.sendInputNotify()` 高层方法。
- **群成员详情**：`GET /v2/groups/{group_openid}/members/{member_openid}` 未封装；应映射为 `bot.getGuildMember()` 或明确的 QQ 内部 API，并补充成员模型。
- **机器人资料页分享链接**：`POST /v2/generate_url_link` 未封装；可提供 `bot.internal.generateUrlLink(callbackData?)`，用于邀请/来源归因。
- **图片校验发送**：普通单聊和群聊发送支持 `force_verify_image_resource`，当前类型与发送配置未暴露，无法选择“图片转存失败则整条消息失败”的可靠模式。

### 事件与行为映射缺口

- **订阅消息授权状态**：网关 `SUBSCRIBE_MESSAGE_STATUS` 尚未声明和转换为 Koishi 事件，无法取得 `subscribe_id` 或用户允许/拒绝结果。
- **群聊与单聊主动消息权限变化**：`GROUP_MSG_REJECT`、`GROUP_MSG_RECEIVE`、`C2C_MSG_REJECT`、`C2C_MSG_RECEIVE` 等事件尚未形成统一的 Koishi 事件，业务插件无法据此停止或恢复主动发送。
- **好友添加来源字段**：`FRIEND_ADD` 新增 `short_code`，当前事件类型/解码未暴露；与分享链接能力应一起实现。
- **互动召回**：官方单聊发送和流式接口支持 `is_wakeup`，底层流式选项已预留，但普通 `session.send()` 没有受控的高层入口、周期额度提示或失败处理策略。

### 已有底层 API，仍可完善的部分

- **指令面板关联对象**：已封装 `updateCommandPanelTargets()`，但当前 Console 只管理全量生效的 `c2c` 与 `group` 面板，尚未提供指定用户/指定群选择器，也未启用 `channel`、`dm` scope。
- **自定义菜单**：已可读取、覆盖保存整个菜单 JSON；暂未提供针对 `switch`、`send_message`、`link`、二级菜单的结构化表单和本地草稿校验。
- **流式消息**：已支持 `append`、`replace`、`text`、`markdown`、`event_id`、`msg_id`、`msg_seq`、`is_wakeup` 的底层会话；自动流式只针对纯文本私聊，富媒体和生成过程分片必须由业务插件显式调用 `bot.stream()`。

### 本次文档增量已确认但不需要新增适配

- 群禁言最大 30 天、撤回权限说明、按钮交互 ID 说明均是规则或文案澄清；现有禁言与撤回接口不需要调整。
- 群/单聊消息引用的 `ext_info.ref_idx` 已由当前适配器在发送后登记并用于后续引用，无需重复实现。
